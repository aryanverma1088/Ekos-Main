## Honest caveats

**1. Recall@5/10 = 1.000 across every system is a property of the eval set,
not evidence any system is unusually good.** The 18-query ground truth set
was authored as close paraphrases of a 24-chunk corpus. At this scale and
with this query style, all four systems saturate recall. This is expected
and documented here so it isn't mistaken for a stronger result than it is.
A meaningful comparison needs either a larger corpus, harder/more
adversarial queries (see #3), or both — noted as follow-up work below.

**2. System D (Hybrid + Rerank) scores at or below System C (Hybrid) on
every metric.** Traced this to a specific case rather than treating it as
noise: query q04 ("What is the company's reimbursement limit for
expenses?") has one ground-truth-relevant chunk, from **finance-expense-
policy-v2** (current). Hybrid RRF ranks v2 fractionally above its
superseded predecessor **finance-expense-policy-v1** (their text is
near-identical apart from the dollar figure, so BM25/dense scores are
almost tied). The TF-IDF fallback reranker (see caveat #3) then **reverses
that order**, ranking the superseded v1 above the current v2 — it has no
authority/recency signal, only lexical similarity, and the two documents
are lexically nearly identical.

This is not a defect in the reranking *mechanism* — it's the expected
result of reranking on text similarity alone when two candidates are
near-duplicates that differ mainly in a fact that changed between
versions. It's precisely the gap the architecture's planned **metadata-
aware ranking adjustment** (authority level + recency boost, applied
*after* reranking, per `docs/architecture.md`) and the **outdated-
detection integrity engine** (Phase 6) exist to close. This case is a
good demo candidate for illustrating why EKOS needs more than a bare IR
pipeline.

**3. The reranker and dense encoder are fallback implementations, not the
final ones.** This sandboxed dev environment cannot reach huggingface.co,
so:
  - System B / D's "dense" signal is LSA (TF-IDF + TruncatedSVD), not a
    real sentence embedding model. Manual stress-testing (see git history /
    `docs/architecture.md`) shows LSA correctly identifies topic but can
    miss vocabulary-mismatched paraphrases that a transformer model would
    likely catch, and can rank a superseded version over the current one
    when their vocabulary overlaps almost completely.
  - System D's rerank step is a per-query TF-IDF cosine rescoring, not a
    trained cross-encoder.

Both are swappable to the real implementations (`sentence-transformers`
`all-MiniLM-L6-v2` encoder, `cross-encoder/ms-marco-MiniLM-L-6-v2`
reranker) via one-line config changes (`ir/embeddings/config.py`,
`ir/reranking/config.py`) once running with internet access. **Re-running
the full evaluation with the real models before submission is a
recommended follow-up** — the comparison table's qualitative story (which
system wins where) may well change, and should be re-verified rather than
assumed to carry over from the fallback results.

## Recommended follow-ups before treating this table as final

1. Re-run all four `evaluate_*.py` scripts with `ENCODER_TYPE =
   "sentence_transformer"` and `RERANKER_TYPE = "cross_encoder"` (requires
   internet access) and regenerate the comparison table.
2. Consider adding a few genuinely adversarial queries to
   `data/ground_truth/queries.json` — ones using vocabulary that doesn't
   appear in the source text at all — to stop recall from saturating at
   1.000 and produce a comparison with more separation between systems.
3. Once the metadata-aware authority/recency boost (post-rerank step) is
   implemented, re-run q04 specifically to confirm it corrects the
   v1-over-v2 ranking issue described above.
